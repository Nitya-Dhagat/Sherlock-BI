# Sherlock-BI (WhyBot) — Project Audit

Audit date: 2026-10-28 (hackathon event day 1). Sources: `docs/WhyBot_Team_Playbook.pdf` (the only
requirements document; 12 pages, read in full), the code in `src/`, `contract/schemas.json`, `data/scenario.yaml`,
tests, and Git history. "Verified" means I ran it; "assumed" is marked as such.

## 1. What the project is

WhyBot answers *"Why did revenue drop?"* on the UCI Online Retail II dataset (UK online retailer, ~1.07M raw rows,
2009-12-01 → 2011-12-09). An LLM (Claude) chooses which deterministic tool to call next and writes the report;
**all numbers come from code**, a validator rejects any number not in a tool output, and the confidence score is
computed by code. It identifies the *behavioural* driver of a change (where / who / how), never a proven cause.

Owners (playbook §2): Nitya — agent, evidence store, validator, confidence, integration; Nisaj — data layer and
4 core tools; Mugdha — significance_test, external factors, forecast, Streamlit UI, demo scenario.

## 2. Architecture as implemented (verified)

```
data/raw/online_retail_II.xlsx
   │ src/build_data.py          (both sheets → snake_case columns)
   ▼
data/clean/transactions_raw.parquet
   │ src/build_clean.py         (dedupe, flags, product-line filter, bulk buy-and-cancel removal, metric tables)
   ▼
data/clean/whybot.duckdb  (+ product_lines.parquet, daily/weekly_metrics.csv, clean_report.json)
   │                           src/make_scenario.py → data/scenario/whybot_scenario.duckdb (labelled synthetic plant)
   ▼  read-only, chosen by env var WHYBOT_DB
src/tools/common.py  ── shared period resolution, segments as of period start, metric definitions, ToolError
src/tools/{detect_anomaly, drill_down, driver_decomposition, customer_movement, significance_test}.py
   ▼
src/agent/runner.py   ── tool discovery, evidence ids E1.., contract validation, errors → {"error": {...}}
src/agent/confidence.py  compute_confidence(evidence)      src/agent/validator.py  check_report(report, evidence)
   ▼
[MISSING] agent loop (Claude tool use + submit_report), Streamlit UI, cache/replay
```

`contract/schemas.json` is generated by `src/contract_init.py`, which also writes one stub fixture per tool in
`src/tools/stubs/` and validates them.

## 4. Maturity

**Partial implementation, approaching a functional MVP for the analytic layer.**
- **Works:** data rebuild, 5 analytic tools, runner/evidence store, confidence, validator, synthetic scenario. 34 tests pass on the scenario DB.
- **Needs improvement:** STL z-score scale (R4) and confidence specificity (R12).
- **Missing:** the agent loop, which is the product itself. Also missing: external factors, forecast, category, UI, cache, evaluation set.
- **Cannot be verified here:** live Claude calls (no SDK or key), and whether the UI exists outside this repo.

It is **not** production-ready.

- `__pycache__/*.pyc` (11 files) and `.DS_Store` were tracked. They are now untracked; the local files are kept.
- `src/tools/tempCodeRunnerFile.py` was tracked: a VS Code Code Runner temp file holding an older `detect_anomaly` that imports names not in `common.py`. It is now untracked; the local file is kept.
- The first line of `.gitignore` was merged (`venvdata/clean/whybot.duckdb`), and caches, `.env` and `.DS_Store` were not ignored. Fixed.
- No dependency manifest existed, and `statsmodels` (required by detect_anomaly's STL check) was missing from the venv. `requirements.txt` is added.
- `data/clean/whybot.duckdb` (15 MB) is in history from earlier commits but no longer tracked. No blob in history exceeds GitHub's 100 MB limit (largest: the raw Excel, 45.6 MB), so no history rewrite is needed.
- Not changed: `data/scenario/transactions_clean.parquet` is tracked, but the matching `data/clean/` file is ignored. The data-sharing policy for generated Parquet is the team's call.
